## Decisions

- inish.in is the public home of Nish Daily. The feed itself is the root page.
- The daily deploy (`deploy_daily.sh`) takes the accepted edition from a pristine snapshot of `origin/main` fetched inside the script, never from the local workdir, so a checkout left on a topic branch cannot stall live delivery. Its only freshness gate is refusing to roll the live site back to an edition older than what the live hostname serves; whole live parity is enforced loudly by `verify_live.py`.
- The "deliver the merged edge head to live" item is an operational act, not a code change: merged commits reach inish.in only via `scripts/deploy_daily.sh` (or the daily publisher run). The deploy-free staleness check `scripts/check_live_current.sh` is scheduled by the VPS systemd timer `live-current-check.timer` (hourly at `*:02`), not by GitHub scheduling: PR #81 removed the `schedule` trigger, and the `Live current check` workflow (`.github/workflows/live-current-check.yml`, added 2026-08-11 in PR #51) remains only as the manual dispatch path. Delivered 2026-08-12: merged head `d5d2b22` (#63 raster social card, #64 deploy rollback) was deployed and re-verified live (`verified_live_current commit=d5d2b22`); the item's close condition is met, so the lane should not re-dispatch it unless a later merged change again goes un-deployed (the hourly check reds `LIVE_IS_STALE` when that happens).
- The "make the hourly Live current check resilient to the GitHub schedule stall" item is done: PR #81 (merged 2026-08-18, commit `1d082f5`) removed the `schedule` trigger from `.github/workflows/live-current-check.yml` (GitHub `schedule` events were delivered late or not at all for hours at a time, with 7+ hour silent gaps, recurring since 2026-08-10) and moved the hourly cadence to the VPS's own systemd timer: `install/live-current-check.timer` → `install/live-current-check.service` → `scripts/run_live_current_check.sh`, installed on netcup-rs2000 since 2026-08-15 as `/etc/systemd/system/live-current-check.{service,timer}` and `/usr/local/sbin/run_live_current_check.sh`. The wrapper fetches origin/main into a private cache clone (`~/.cache/inish-live-current-check/main`), derives the accepted SHA from FETCH_HEAD, and runs that commit's `check_live_current.sh` — never a hardcoded hash or an installed copy. The timer has fired hourly at status=0/SUCCESS with `verified_live_current commit=<main HEAD>` every hour since install; re-verified 2026-08-21 (PR #98, lane report `.lane/reports/lane1-live-current-check-resilient-redispatch-2026-08-21.md`). Do not re-dispatch this item: the hourly sweep is off GitHub's scheduler by design, and the only new trigger is the timer unit failing (`systemctl --failed`, or a missed fire in `journalctl -u live-current-check.service`).
- The edition is gated on quality, not count. `build_daily.py` accepts 0-8 stories and a day where nothing survives being checked is a valid edition. Never pad to hit a number.
- Every story carries a `fact` (a checkable detail from the source), a first-person `take`, and a `caveat`. The builder enforces all three and refuses to render generic copy — that validator is the editorial policy, so weakening it to make a run pass defeats its whole purpose.
- Keep only the current feed plus its RSS, JSON, robots, sitemap, CSS, and JavaScript endpoints. Do not publish founder/product pages, LLM pages, or edition archives.
- Preserve old non-archive `/daily/*` links with permanent redirects to the root equivalents; archive URLs intentionally return 404.
- The site should stay static HTML, CSS, JavaScript, and Cloudflare Pages unless a stronger need is proven.
- The cross-repo "link inish.in back from product sites" item (backlog cd1a458ea0) is owned by the 0509 and tinystudio-io loops, not this repo: the footer attribution edits live in nish3451/0509 (`app/components/marketing-footer.tsx`, PR #599) and nish3451/TinyStudio.io (`public/index.html` footer, PR #70), both labeled "Nish's daily reads" → https://inish.in/. This repo has no code change for it; close the item when `curl -sL https://0509.io/` and `https://tinystudio.io/` both contain an href to `https://inish.in/`. siterep.net, seofixkit.com, and aiconverter.app stay out of scope until they gain attribution chrome.
- The public GitHub profile website field (`github.com/nish3451` → profile → website) is a manual account write, not a fleet action: the machine's gh token (scopes `gist`, `read:org`, `repo`, `workflow`) lacks the `user` scope, so `PATCH /user` fails with "This API operation needs the 'user' scope". Re-verified 2026-08-20: `gh api users/nish3451 --jq .blog` now returns `nish.sh` — the field was set manually between 2026-08-15 and 2026-08-20 (it was `""` on 2026-08-15), but `PATCH /user` still returns 404 with the same scope error, so the lane still cannot set it to the intended `https://inish.in/`. GraphQL is not an alternative route — the schema has no `updateUser` mutation, and `gh auth refresh -h github.com -s user` is an interactive device flow. The intended value is `https://inish.in/`; verify with `gh api users/nish3451 --jq .blog`. Do not re-dispatch this item until the field is set to `https://inish.in/` (github.com/settings/profile) or a `user`-scoped token exists. Prior records: PR #43 (closed, same finding, 2026-08-10), re-verified 2026-08-12 (#62), re-verified 2026-08-15 (#74), re-dispatch 2026-08-15 (#82).
- The "every Checked fact links to its exact evidence" item is done: PR #58 (merged 2026-08-12) made `evidence_url` a required story field, the builder validates it as a public HTTPS URL and renders the Checked line as a link to it, and tests pin the contract (cross-source fact links to the discussion thread while the story keeps its own primary link). ## Rejected Paths

- Banning filler words in the runbook. A wordlist (`useful`, `concrete`, `durable`, `lens`, `unlock`) was tried on 2026-08-03 and the writer simply rotated to `visible`, `bounded`, `trust`, `honest`. Structural constraints the builder can enforce work; vocabulary bans do not.
- Sourcing candidates from brand-new GitHub repositories. `created:>=7 days stars:>=15` returned projects whose only evidence was their own README, which is why six of eight stories in one edition were repo descriptions rewritten as news.
