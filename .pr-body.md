Standing rule (fleet-ops#524) requires every product repo to ship a `.claude/skills/verify-<app>/SKILL.md` so the `fleet-verify-harness-canary` (heartbeat block 29) can observe-to-close the missing-harness gap. `Nishfleet/fleet-ops#963` is a stale re-firing of `Nishfleet/fleet-ops#770`: PR #138 landed `verify-inish-site` on `origin/main` 45 seconds before the canary tick that re-filed the issue, and the canary's `ORIGIN_FALLBACK=1` mode (added in fleet-ops#927) now treats the local-checkout lag as `ok`.

This PR is the no-fix-implementation-noop. The harness is already on `origin/main` (commit `03c2884`); the only change is a CI-loud pin that makes the harness's presence a gate on this repo's own test workflow, so the gap cannot re-occur via a missing or accidentally-reverted file.

## What ships

- `tests/test_verify_harness_present.test.mjs` — a Node `node:test` discovery test that mirrors the canary's local-only path:
  - asserts `.claude/skills/verify-inish-site/SKILL.md` exists,
  - asserts the YAML frontmatter declares `name:` and `description:` (the `name` must match the directory — the canary matches on `verify-<app>`),
  - asserts the five required headings (`LAUNCH`, `DOCTOR`, `DRIVE`, `EVIDENCE`, `CLEANUP`) are present (matching the canary's regex shape so `##LAUNCH` or `## LAUNCHING` does not silently pass),
  - asserts the `features/` map is a non-empty directory of kebab-case `.md` files (the canary's `features_on_head()` regex),
  - asserts the LAUNCH contract points at `scripts/launch_local.sh` (the file's name appears in `SKILL.md`),
  - asserts the in-process worker test (`tests/test_worker_edge.test.mjs`) and the live E2E script (`scripts/verify_live.py`) the harness advertises still exist on disk,
  - asserts the skill directory ends with `/verify-inish-site` (canary regex).
- No other files changed.

The test is auto-discovered by the existing CI workflow (`.github/workflows/tests.yml` already runs `node --test "tests/**/*.test.mjs"`), so no CI wiring change is needed.
